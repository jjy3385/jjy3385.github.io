# 프로젝트1 - Threads
핀토스 프로젝트1의 주제는 스레드(threads)<br>
CPU 스케줄링과 동기화에 대해 배울 수 있음<br>
설명을 하기 위해 핀토스 맥락에서의 해당 개념에 대한 설명이 필요함<br>

## 스레드
공부를 할 때 일반적으로 우리는 프로세스가 있고 그 안에 여러 스레드가 있을 수 있다는 식으로 배움<br>
그게 틀린건 아닌데 핀토스에서는 프로세스 = 스레드임

이제 스레드 자체 개념인데 스레드는 실행 흐름 자체를 추상화한 것이라고 볼 수 있음
이게 뭔소리냐면 스레드에는 CPU 레지스터의 값들을 저장할 수 있는 공간이 따로 있음<br>
핀토스에서는 `intr_frame` <br>
CPU 레지스터의 값들을 저장한다는게 무슨 뜻이냐면 어떤 프로세스 안에서 CPU가 실행되던 그 문맥(Context)를 그대로 복제할 수 있다는 뜻이고 그렇다는 것은 실행 흐름을 제어할 수 있다는 것을 의미함<br>
그래서 핀토스에서는 스레드라는 자료구조를 리스트에 담아서 스케줄링 함으로써 CPU 흐름 자체를 스케줄링 할 수 있는 것

## 스케줄링
핀토스는 CPU가 하나이기 때문에 한번에 하나의 스레드만을 실행할 수 있음<br>
하지만 우리가 실제 운영체제가 작동하는 것을 보면 여러 스레드(프로세스)가 동시에 실행되는 것처럼 느낌<br>
왜냐하면 엄청나게 빠른 속도로 문맥 전환(Context Switching)이 일어나고 있기 떄문임
이 때, 이 문맥전환을 어떤 규칙으로 할 것인가? 그게 스케줄링임
즉, 이번엔 어떤 스레드가 CPU자원을 할당받을 차례인지를 결정하는 알고리즘이라고 생각할 수 있음

## 동기화
이게 좀 어려움<br>
우리는 동기화를 통해 실행흐름을 맘 껏 조작할 수 있게 됨<br>
스케줄링은 어떤 스레드가 CPU의 자원을 할당받을지 결정하는 것이라면 동기화는 실행되고 있는 코드 흐름 자체를 제어하는 것<br>
특히 공유 자원에 대해 여러 스레드가 동시에 접근할 때 그것을 제어하는 것임<br>

대충 개념적인 설명은 이정도로 하고 프로젝트1의 소주제로 넘어가보자

## 프로젝트1 소주제
1. Alarm Clock (알람 클락)
    - Clock 이라는 하드웨어와 OS가 어떻게 여러 프로세스가 동시에 돌아가는 것처럼 느끼도록 만드는지 이해할 수 있게 도와줌
2. Priority Scheduling (우선순위 스케줄링)
    - 각 스레드는 우선순위라는 걸 갖고 있음, 그 우선순위에 따라 스레드를 줄세우는 스케줄링 알고리즘을 구현함
3. Advanced Scheduler
    - 실제 OS에서 쓰이는 MLFQ(Multi-Level Feedback Queue) 스케줄러를 구현함


## 그냥 잡생각

막 실행흐름이 어쩌고 스케줄링이 어쩌고 용어가 어렵지만 하다보면 결국은 자료구조와 알고리즘일 뿐이란 걸 알게 됨<br>
하드웨어를 다루는 시스템 동작이던 그냥 일반 응용 프로그램 개발이던 개발은 그냥 자료구조와 알고리즘일 뿐이란 걸 기억하면 쫄지 않을 수 있고 그렇기에 개발자는 기본기가 중요한 것이란걸 또 새삼 느낌<br>

## 추가적인 사항

실행환경과 기본적인 테스트, 프로젝트 구조에 대한 내용도 기록을 해둘 필요가 있을것 같아 남김<br>

일단 내 실행환경은 OS가 윈도우인데 WSL2 깔아서 도커 컨테이너 올린 형태임<br>
도커 컨테이너는 Ubuntu 22.04 amd64 이미지를 base로 함<br>

### CRLF (개행문자) 수정

문제가 되는건 개행문자<br>
    - 윈도우는 기본이 \r\n (CRLF)인데 리눅스는 \n (LF)<br>
    - 그래서 셸 세션에 pintos 실행 경로 설정하는 activate 파일이랑 실제 실행파일인 pintos 를 LF로 바꿔줘야 했음<br>
> /pintos/activate      
/pintos/utils/pintos


### 테스트 방법

테스트를 위한 명령마저 다양함...<br>
일단 제일 쉬운거 터미널의 자기 프로젝트 경로에서 `make check` <br>
예를 들어, 프로젝트1 스레드라면 `/pintos/threads` 경로에서 `make check` 입력<br>
모든 테스트케이스를 한번에 돌릴 떄 쓰는 명령어<br>
이 명령이 왜 되는지는 Makefile 이랑 다 뜯어봐야되서 복잡...<br>
걍 그거 몰라도 됨, 쓰면 됨...

테스트케이스를 개별적으로 하기 위한 명령도 있음<br>
직접 /pintos/utils/pintos 파일을 실행하는 형태<br>
alarm-single 이라는 테스트를 해보고 싶다면 make 명령어로 빌드를 한 후 `/pintos/threads/build/` 에서 아래와 같이 입력해보면 됨<br>
> pintos -v -k -T 60 -m 20   -- -q   run alarm-single

복잡해 보이지만 -- 기준으로 뒷쪽이 커널 실행 시 입력될 인자라는 것 정도만 기억하고 나머지 옵션들은 그때 그때 검색해서 추가하면 됨<br>
예시로 `-m 20` 옵션은 QEMU에 할당한 메모리 용량을 `20MB` 로 지정한다는 뜻이다.
